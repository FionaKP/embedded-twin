# Component Model SDK

The contract every component model obeys — hand-written now, generated by the
datasheet-reading model factory later (roadmap v0.3). A model is one Python
class; the datasheet is its spec.

## Anatomy

```python
from twin.components.base import Component, register
from twin.core import Drive

@register("vendor.part_family")          # key used by BOM/part-table binding
class MyPart(Component):
    """One-line description (shown by `twin models`).

    params: threshold_v (1.8), i_active_ua (120)   # document defaults
    """

    def start(self):                     # called at power-on
        self.out = self.require_net("OUT")           # pins by name or number
        self.sense = self.require_net("SENSE")
        self.sense.listen(self._on_sense)            # react to the board
        self.kernel.schedule(1_000_000, self._tick)  # or to time (ns)
        self.set_load("+3V3", 120e-6)                # power engine, amps
        self.set_state("monitoring")                 # traced state machine

    def _on_sense(self, net):
        v = net.voltage or 0.0
        self.drive("OUT", Drive.low() if v < self.params.get("threshold_v", 1.8)
                   else Drive.release())             # open-drain style
```

## The rules

1. **Datasheet-derived numbers only** — currents, timings, thresholds come
   from the part's datasheet tables; defaults documented in the docstring,
   overridable via `params` (BOM `param:*` columns or scenario overrides).
2. **All randomness via `self.kernel.rng`** — never `random`/time-of-day.
   Determinism is load-bearing.
3. **Power honesty** — every operating state calls `set_load(rail, amps)`;
   heat via `set_dissipation(watts)` + a thermal node if the part gets warm.
4. **State machines are traced** — `set_state()` on every meaningful
   transition; `log()` for events a debugging engineer would want to see.
5. **Buses**: UART via `twin.comm.Uart` (attach to pin nets), I2C via
   `I2CBus.on_nets(...).attach(addr, self)` implementing
   `i2c_write/i2c_read`.
6. **Never crash the board** — missing optional pins are tolerated
   (`self.net(...)` returns None); required pins use `require_net` so a
   miswired board fails loudly at build.

## Conformance tests (the factory's feedback loop)

Each model ships a pytest that checks its datasheet claims against the sim:
build a minimal synthetic `BoardIR` around the part (see
`tests/test_board_and_power.py::synth_battery_board`), run, assert currents,
timings, and protocol behavior. A model without conformance tests is a
hypothesis, not a model.
